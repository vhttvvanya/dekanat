# Онлайн-деканат — презентация (до 10 слайдов)

Скопируйте блоки в Google Slides / PowerPoint. На защите показать три типа документов и случай без данных.

## 1. Проблема
Деканат вручную читает фото справок и заявлений, переносит поля и ищет пункты Положений. Студент ждёт ответ без ссылки на правило.

## 2. Решение
Цифровой секретарь в одном пайплайне: распознать текст → заполнить карточку → ответить по Положению со ссылкой на поле или пункт.

## 3. Демо: справка об обучении
Пример `open-001`. Вопрос: «Содержит ли документ все обязательные сведения по Положению?»  
Ожидание: все поля найдены, источники `rule:3.1`, `rule:3.2`, `rule:3.3`. Решение принимает сотрудник деканата.

## 4. Демо: заявление на отпуск
Пример `open-011`. Карточка: ФИО, группа, курс, причина, даты, подпись студента. Печать для этого типа не требуется (п. 4.3).

## 5. Демо: справка о практике
Пример `open-021`. Поля организации, сроков, руководителя, оценки, подписи и печати.

## 6. Чего не хватает
Пример `open-002`: нет даты выдачи. Ответ перечисляет пропуск и ссылается на п. 3.1. Остальные поля всё равно извлекаются.

## 7. Ответа нет
Вопрос: «Какова стоимость обучения?»  
Сервис не выдумывает: `answerable: false`, пустые источники, рекомендация обратиться в деканат.

## 8. Стек
Python 3.11, Streamlit, Tesseract 5 (`rus`+`eng`), PyMuPDF, Pillow, PyYAML. Внешние OCR/LLM API не используются. Новый тип документа добавляется в `configs/fields.yaml`.

## 9. Сдача
Репозиторий с README. `python predict.py` пишет `results/results.json`. Локальная оценка: `python evaluate.py --reference data/reference_results.json --predictions results/results.json`.

## 10. Ограничения
Одна страница JPG/PNG/PDF до 15 МБ. Подпись и печать — эвристика по изображению, не экспертиза подлинности. Итоговое решение всегда за сотрудником деканата.
