# Онлайн-деканат

Локальный сервис для кейса хакатона «Онлайн-деканат». Студент загружает JPG, PNG или одностраничный PDF и задаёт вопрос по документу; сервис распознаёт текст, заполняет карточку, проверяет обязательные сведения по `data/rules.md` и отвечает со ссылкой на поле или пункт Положения.

Это только предварительная проверка: сервис не принимает решение за вуз и не определяет подлинность подписи или печати. OCR выполняется локально Tesseract; внешние OCR- и языковые API не используются.

## Возможности и критерии кейса

- Принимает JPG, JPEG, PNG и одностраничные PDF до 15 МБ; тип можно выбрать вручную.
- Распознаёт русский текст локально через Tesseract 5. Для PDF с текстовым слоем использует точный текст и дополнительно анализирует изображение для проверки графических отметок.
- Заполняет все поля выбранного типа; отсутствующие текстовые значения показываются как `не найдено`, даты нормализуются в `YYYY-MM-DD`.
- Проверяет комплектность по конкретным пунктам Положения. На вопросы о полях отвечает по документу; когда документ и Положение не содержат ответа, сообщает об этом и рекомендует обратиться в деканат.
- Не делает юридического заключения: окончательное решение принимает сотрудник деканата.
- Дополнительные возможности: автоопределение типа, добавление типа документа через YAML, подсветка найденных полей на изображении и отдельная кнопка проверки комплектности.
- Пакетная обработка набора документов сохраняет `results.json` для локального evaluator.

## Стек и зависимости

- Python 3.10+
- Streamlit — интерфейс
- Tesseract 5 с языковыми данными `rus` — локальный OCR
- PyMuPDF — чтение и растеризация PDF
- Pillow — обработка изображений и проверка графических отметок
- pytesseract — Python-интерфейс к Tesseract
- PyYAML — загрузка конфигурации

Python-зависимости перечислены в `requirements.txt`. Языковые данные Tesseract `rus`, `eng` и `osd` включены в `vendor/tessdata`; исполняемый файл Tesseract устанавливается отдельно.

## Установка системного OCR

Windows (UB-Mannheim):

```powershell
winget install --id UB-Mannheim.TesseractOCR -e
```

Linux (Ubuntu/Debian):

```sh
sudo apt-get update
sudo apt-get install -y tesseract-ocr tesseract-ocr-rus
```

Убедитесь, что исполняемый файл доступен и русский язык установлен:

```sh
tesseract --list-langs
```

Если системный Tesseract не содержит `rus`, приложение использует включённый файл `vendor/tessdata/rus.traineddata`. Путь к установленному исполняемому файлу ищется автоматически.

## Установка Python-зависимостей

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app/main.py --server.port 8501
```

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app/main.py --server.port 8501
```

Откройте <http://localhost:8501>. Для ручной проверки загрузите JPG/PNG или PDF; либо выберите один из 30 учебных примеров в боковой панели.

## Настройка и примеры

- Типы, подписи полей, алиасы OCR и пункты правил задаются в `configs/fields.yaml`.
- Тексты правил — в `data/rules.md`. Это единственная база правил для данного кейса.
- `open-001`: вопрос «Содержит ли документ все обязательные сведения по Положению?» — полный пример справки.
- `open-002`: та же проверка неполного документа — отсутствует дата выдачи.
- `open-011`: вопрос «Укажи значение поля „Учебная группа“» — проверка карточки заявления.
- `open-021`: проверка справки о практике.
- На любом примере задайте вопрос «Какова стоимость обучения?» — сервис должен честно ответить, что данных нет.

Для проверки чистого OCR загрузите, например, `data/documents/open-001.png`. В интерфейсе будут доступны распознанный текст, карточка, источники и подсветка найденных полей.

## Результаты автопроверки

Запустить все открытые примеры и записать `results/results.json`:

```sh
python predict.py --output results/results.json
```

Сравнить результат с открытой эталонной разметкой:

```sh
python evaluate.py --reference data/reference_results.json --predictions results/results.json
```

Для закрытого набора организаторов укажите его каталог, манифест и вопросы. Имена типов в манифесте должны соответствовать `configs/fields.yaml`:

```powershell
python predict.py --data-dir путь\к\закрытому --manifest путь\к\documents.json --questions путь\к\questions.json --output results/results.json
```

Типы документов в манифесте известны заранее. Флаг `--auto-detect` включает бонусное автоопределение типа.

Формат `results.json` и метрики описаны в `data/DATASET_README.md`; `evaluate.py` использует только стандартную библиотеку Python. Закрытые проверочные документы в этом архиве отсутствуют, поэтому приложенный `results/results.json` строится по 30 открытым примерам.

## Тесты

```sh
python -m unittest discover -s tests -v
```

Учебные PNG/PDF можно повторно собрать из эталонной разметки:

```sh
python tools/generate_documents.py
```

## Проверка критериев

| Критерий | Как проверить |
|---|---|
| Загрузка JPG, PNG и одностраничного PDF | Загрузить файл в интерфейсе; неподдерживаемый формат и многостраничный PDF должны получить понятную ошибку |
| OCR и карточка трёх типов документов | Загрузить `open-001.png`, `open-011.png` и `open-021.png`; сверить текст и поля с документами |
| Пропущенные поля обозначаются `не найдено` | Проверить `open-002` и другие неполные примеры; остальные поля должны остаться доступными |
| Комплектность с источниками | Для полного примера проверить пункты 3.1–3.3, 4.1–4.2 или 5.1–5.3; для неполного — только пункты пропущенных сведений |
| Ответы по полям и честный отказ без данных | Спросить значение поля и вопрос о стоимости обучения; проверить `sources` в карточке ответа/JSON |
| Воспроизводимый формат выгрузки | Выполнить `python predict.py`, затем официальный `python evaluate.py` |
| Не ломаются даты, извлечение и правила | Выполнить `python -m unittest discover -s tests -v` |

## Структура проекта

```text
app/             интерфейс, OCR и пайплайн обработки
configs/         типы документов, поля, алиасы и требования
data/            правила, вопросы, эталон, манифест и примеры
docs/            сценарий демо и содержание презентации
results/         результаты пакетной обработки
tests/           быстрые модульные проверки
tools/           генератор учебных документов
vendor/tessdata/ языковые данные Tesseract
evaluate.py      официальный evaluator набора
predict.py       пакетная обработка документов и вопросов
```

Новый тип документа можно добавить без изменения кода: добавьте описание `label`, `detect_keywords`, `required_rules` и `fields` в `configs/fields.yaml`, затем внесите соответствующие пункты в `data/rules.md`.

## Ограничения

- Только одна страница; размер файла — до 15 МБ.
- Набор предназначен для читаемых печатных документов. Рукописный текст, поворот, сильные тени и шум могут привести к `не найдено`.
- Наличие подписи и печати определяется эвристикой по изображению, это не проверка подлинности.
- Решение о принятии документа всегда принимает сотрудник деканата.
